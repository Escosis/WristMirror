# 腕镜

利用替换法为华为手表安装本地第三方 HWT 表盘，支持采用兼容表盘协议的 GT、FIT 等设备，并为直接传输失灵的新鸿蒙固件提供既有资源替换路径。

## 替换法的原理

手表把普通表盘作为带有**资源 ID、协议版本和类型状态**的资源管理。文件上传和资源接纳是两个不同阶段：新固件的普通下载流程还会校验服务器授权、账户／设备绑定以及内容摘要。因此，把一个本地 HWT 传完，并不意味着它会成为可使用的新表盘。

替换法不为任意新 ID 建立下载条目，而是使用手表上**已经登记、允许操作的普通表盘资源槽**，发起同一 ID 的新版本替换事务。在允许这种替换路径的固件实现中，既有资源的登记／许可上下文可以被沿用，使普通直接安装失败的本地内容仍有机会通过更新已有资源完成部署。是否沿用许可缓存、内部状态或重新检查待接收资源，最终由设备固件决定；这不是关闭固件验签，也不是在手机上生成服务器签名。

腕镜的实际流程是：

1. **建立会话。** 通过蓝牙完成设备认证与会话密钥协商，随后读取手表真实的 `0x27/0x02` 表盘列表，保留资源 ID、版本及原始类型位。预置、相册、视频、趣味贴纸等特殊资源不作为普通替换目标。
2. **准备原始载荷。** 从 HWT 容器提取内部 `watchface.bin`，在本机冻结并校验副本。XML 描述、二进制头和资源字节均不改写；HWT 描述版本与传输任务使用的协议版本分别处理。
3. **协商替换。** 点击替换时捕获当前连接、唯一目标 ID、原协议版本和冻结载荷，确认时再重验这些条件；将协议版本最后一个数字字段加一，以 `0x27/0x03` 的应用操作请求新版本。不伪造授权字段；只有对应操作的真实回包明确给出 `error=0`、`need=1`，才开始一次文件传输。`need=0` 表示设备未要求新文件，不强行上传或自动改版重试。
4. **完成标准传输。** 通过 `0x28` 协议登记文件、取得设备分配的文件 ID、协商传输单位与加密方式，并响应摘要、分块及终结回执。任务文件名按资源 ID 和协议版本构造，发送内容始终是已冻结的原始二进制。
5. **核验应用结果。** 传输结果与表盘应用报告分别记录；设备完成报告驱动后置应用操作，再查询新的表盘列表，核对同一 ID 的候选版本。仅凭手机发送完成或进度达到 100% 不判断安装成功，最终画面仍应在手表上确认。

这个方法依赖既有普通资源以及设备允许的版本替换行为，不等同于所有型号、固件或任意全新 ID 都能免授权安装。请选用适合设备且有权使用的 HWT。

## 使用

- 在设备页添加手表并配置华为 ID；点击历史设备可打开设备详情，连接手表、配置该设备的华为 ID 或解除配对。主页显示已选择设备的型号代码、蓝牙地址及连接时读取的信息。型号代码和序列号首次取得后按设备缓存，断开连接仍保留；点击信息文本即可复制。运行日志可在设置页打开，支持查看、清空与导出。
- 在表盘页选择 HWT、选择要覆盖的普通表盘，点击替换并确认。对话框显示替换进度与结果，操作结束后可返回或关闭。选择文件本身不会向手表传输。
- 删除沿用目标原 ID 与版本，完成后重新查询列表。删除后无法直接恢复，操作结束请核对手表画面。
- 在设备页选择“解除配对”，确认后解除手机系统配对并清除本应用该设备的连接记录与凭据。系统限制直接解除时，按提示进入系统蓝牙设置，返回后验证状态再清理；其他设备、其他应用与手表表盘不受本机记录清理影响。

## 编译

使用支持现有 Android Gradle 插件的 Android Studio，Gradle JDK 选择 **21**，安装 Android SDK **37.0** 与 Build Tools **37.0.0**。依赖和工具版本由工程配置与依赖锁声明。

```sh
./gradlew :app:assembleDebug :app:testDebugUnitTest
```

Windows 使用 `gradlew.bat` 执行相同任务。调试构建使用 Android Studio 的默认签名；发布签名可通过 `WRISTMIRROR_KEYSTORE`、`WRISTMIRROR_STORE_PASSWORD`、`WRISTMIRROR_KEY_ALIAS`、`WRISTMIRROR_KEY_PASSWORD` 环境变量提供。
